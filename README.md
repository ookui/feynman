# Feynman

本地 macOS 专题与个股研究工作台。打开 `build/Feynman.app` 即可使用。应用适用于 Apple 芯片的 Mac，最低系统版本为 macOS 14。两台 Mac 可以各自选取同一个同步知识库在本机的位置。

## Atlas 与个股深研

Atlas 左侧的 Projects 打开专题，Stocks 打开公司主页。右侧图中的方形代表专题，圆形代表公司。单击节点突出直接关联，双击进入对应页面。专题内的公司实体可建立或关联个股深研；同一家公司的多个专题实体共享一份公司档案。点击公司右栏的专题名称直达该专题的公司实体，右键可打开专题概览。

个股项目位于 `Feynman/stocks/<公司>/`，首页是关键问题看板。研究围绕这家公司 3–5 个决定股价的关键问题展开：每个问题写明市场隐含的假设、判断不同时的股价影响、我的判断、证伪条件和跟踪指标。看板右侧是快照、情景估值、排雷异常、最近一次投资判断和关联专题。左栏依次为关键问题、快照、排雷清单、情景估值、时间线、研究底稿、投资判断和 References。新建个股时可填写「为什么现在看」，开题时 AI 以此为研究缘起。

「AI 研究」菜单运行 `sling-company-study`：开题生成快照、研究底稿、3–5 个候选关键问题和首轮排雷；另有刷新快照、运行排雷清单、补充关键问题、更新时间线和同步命题。点击后先弹出可修改的提示词，确认后按设置中选择的 AI 服务以非交互方式运行（Claude 为 `claude -p`，Codex 为 `codex exec`）。运行窗口显示过程、改动的文件和 AI 的总结，可停止或放到后台；完成后点「查看结果」进入对应页面。权限只允许写入公司目录，同步命题时另允许写入知识库的 `Theses/` 并刷新索引。Claude 需要调用 Wind 时，按 Wind 在本机 Claude CLI 中的服务名，用 `defaults write local.feynman.research claude.allowedTools` 追加授权，默认已含 `mcp__wind-tools`。Claude Code 从 `~/.claude/skills/sling-company-study/` 读取 skill，其他终端按提示词读取同一文件；设置中的「研究指令 › 个股」可改用其他 skill。候选问题以虚线卡片显示，「采纳」后进入看板，「删除」后文件保留 `deleted: true`，AI 不会再起草同样的问题。问题页的「继续研究此问题」由终端直接作答。

快照（`snapshot.json`）与排雷清单（`checklist.json`）由 AI 维护，工作台只显示。排雷正常项一行带过，异常项升级为排雷问题；尚未升级的异常可在清单页手动升级。情景估值由用户在工作台填写，每个情景对应一组关键问题的答案，按 PE、EV/EBIT 或 EV/Sales 计算每股价值，可选折现，并给出相对现价和概率加权结果。时间线中的事件记录日期、出处，以及对各关键问题是支持、削弱还是中性。

行业事实归专题。问题页的「添加行业依据」可引用专题中的问题、概念、实体或事件；专题条目更新后，看板和问题页显示「行业依据已更新」，核对后点「已核对」。研究中出现的行业层面结论，用「提交到专题」写成专题中的问题或事件，正文附回链，本问题自动引用它。专题中已关联个股的公司实体页显示该公司最近的判断与关键问题状态，内容仍在个股项目中维护。

「更新判断」以最近发布的判断为底稿；首次判断的草稿由看板上用户自己写的判断、证伪条件、跟踪指标和情景表汇集而成，之后也可「插入关键问题与情景摘要」。判断可选看多、看空或观望。点击「发布判断」后，正文、原因、方向、预测数字和当时的情景表一起进入历史，随后弹出同步命题的提示词框，确认后把判断同步到 LakeHouse 的 `Theses/`，目标路径记录在 `lakehouse.json`。勾选「保存本次模型版本」会将当时的工作簿另存至 `versions/`。历史默认显示最近三次，可按年份浏览、比较相邻版本或追加勘误。要引用行业证据，在专题原文页点击工具栏的链接按钮，将复制的 Markdown 链接粘贴到判断正文中。

## 编辑、搜索与项目关系图

- 单击正文、列表项或表格单元格即可进入 SimaQ Markdown 编辑器。可以从 Edit、Paragraph、Format 和 Table 菜单插入链接、调整标题、格式化选区或增删表格行列。表格支持整表剪切、复制、删除和矩形选区。列表内按 Tab 缩进，Shift-Tab 提升层级。点击「完成」或按 ⌘S 返回阅读页，再划选报告文字即可创建引文。
- ⌘F 在当前文档搜索，⌘⇧F 搜索整个项目。展开结果可逐条查看上下文，点击命中跳到原文。搜索支持简繁混输、连字符、精确短语、全词、大小写和正则表达式。
- ⌘G 打开 Project Overview。单击节点可突出其关联，双击打开条目或文档，滚轮可缩放。在设置中可修改快捷键。
- 在 Inquiries 或 Entities 条目的「更多」菜单、左栏右键菜单中，可添加或取消核心标记。核心条目在左栏加粗并显示星号。已有问题继续使用原目录和条目 ID。
- 设置中的「默认 AI 服务」可选择 Codex、Gemini 或 Claude。各 CLI 使用各自的可执行文件路径和本机登录，设置页可检测所选 CLI 的版本。
- Claude 的后台研究（`-p` 模式）无法弹出授权确认，工作台预先授权只读工具：Read、Grep、Glob、WebSearch、WebFetch、Skill，Tavily、Exa、anysearch 三个 MCP，以及 alphapai-research 和 anysearch 的数据脚本；知识库根目录以 `--add-dir` 开放读取。不授予 Edit、Write，正文由 Feynman 保存。需要追加的授权规则用逗号分隔写入 `defaults write local.feynman.research claude.allowedTools "规则1,规则2"`。

## 开始研究

按 ⌘[ 回退一页，按 ⌘] 前进一页。⌘← 跳到本次浏览历史的第一页，⌘→ 跳到最后一页。回退后点开新的链接，前进路径会从这里重新开始。

在左栏输入关键词可同时搜索标题和正文，标题命中优先。支持中英文混输、简繁体、忽略大小写与空格，也可以输入相隔的几个词。例如，输入 `AI 资本开支` 可以找到「AI 基础设施的资本开支」。点开结果后可继续浏览同一组匹配。点结果右侧的图钉或「保留全部」，清空搜索后就能在左栏「已保留」中继续打开，重新进入项目也会保留。检索范围包括条目、引文、报告、项目文档、Memo、日志及项目内的 Markdown、TXT、CSV 和带文字层的 PDF 附件。

菜单栏默认跟随 macOS 的首选语言，支持英文、简体中文和繁体中文。在「Feynman → 设置…」（⌘,）中可单独指定语言，重新打开应用后生效。

1. 在设置中选择工作目录。若检测到 LakeHouse，会默认选中它。新项目保存在该目录下的 `Feynman/<项目名称>/`。
2. 新建项目，填写研究意图，点击「开始预研」。所有 AI 调用都先弹出提示词框，可修改后点「开始研究」。工作台按设置中选择的 AI 服务以非交互方式运行（Claude 为 `claude -p`，Codex 为 `codex exec`，Gemini 为 `gemini -p`），窗口中显示过程、改动的文件和 AI 的总结，可停止或「后台继续」，底部状态栏随时可以重新打开。每次运行只允许写入该动作需要的位置：预研写本项目，问题研究和修订只读、由工作台保存回答，回写可写知识库，资料入库只写 Library。每台机器各自使用已有的 CLI 登录与 skill。
3. 首次预研默认使用 `sling-thematic-study`。已有报告的项目点击「继续研究此项目」可以选择具体问题或修订最新报告。追问由 Codex 直接根据当前问题、已有问答及出处作答，修订默认从所选内容开始。设置中可以分别配置这些动作和回写的指令。CLI 路径留空时自动检测，也可以指定可执行文件并测试版本。
4. 问题页点击「AI 研究」，AI 返回的最终 Markdown 回答会自动写入该问题，保留链接与出处。新问题默认「待回答」，点击状态标签可标为黄色「已回答」，再次点击可切回。已有回答的问题再点「AI 研究」时，弹出框只需输入追问；研究完成后也可在结果框中继续追问。每轮把新答案融入已有总结，合并重复观点并保留原有出处。总结下方的「追问记录」默认收起，展开后每轮默认只显示问题，点击问题可查看当轮完整回答和时间；记录随问题保存。其他条目可从「更多」修订正文，在提示词下方写补充问题，回答会整合到相关段落。报告修订另存为新版本。运行中手工改过正文时，结果框提供「查看保留的回答」。AI 写入文件后，打开的工作台会自动刷新。预研对象直接进入大纲；选择条目可编辑，在「更多」中可合并、删除、加入 Memo 或回写知识库。
5. 在报告正文划选可见文字，选概念、实体、事件或问题。可以创建对象，也可以把这处引文关联到已有对象。点击报告高亮时，右栏会列出直接源于这段原文的问题，以及通过该处条目关联的问题。点问题标题即可查看解答。点击对象上的引文可返回原报告版本。
6. 条目页最右侧的关系图在同一张图上显示全部关联，拖动大纲或关系栏的分隔线可以调整宽度，应用会记住设置。宽栏采用两侧弧形布局，中等宽度采用双列，窄栏采用纵向分支。不同条目用有区别的图标表示。节点较多时默认缩放到全图，也可以放大浏览。实线连接它的问题、事件、概念、实体、出处和资料，外围节点之间已记录的关联用虚线显示。将鼠标停在节点上可看完整标题，点节点可打开条目、原文或资料。可切换列表，或用「新建问题」创建与当前条目关联的问题。
   在问题、概念、实体或事件的「更多」菜单中，选「添加参考资料…」可复制本地文件，选「关联知识库资料…」可引用库内原件。每份文件都列在「参考资料」下，并与当前条目建立可双向查看的关联。
   在任意一端打开「关联…」可添加或解除同一条关系。保存后，两端的关系图与列表立即更新，改名会保留关系并更新节点标题。工作台打开期间每两秒自动检查一次外部文件变化。
7. 「参考资料」目录下的「网页链接」集中展示新闻和网址。可从浏览器把地址栏或页面链接拖到左侧「参考资料」，普通网页按标题收录；直接返回 PDF 的链接会下载原件并成为独立文件资料，可预览、关联和保存到知识库 Library。从 Finder 将 PDF、HTML、Markdown、Word 或图片拖到侧栏的「参考资料」或资料页面，每份文件都会成为独立条目。点击报告引用或关系节点可定位到对应网页链接或文件。文件资料打开后直接只读预览全文。可以从右上角关联其他条目、基础报告或引用到 Memo，右侧关系图和列表可跳转到关联页面。
   专题与个股的 References 使用相同的删除规则。删除导入的资料会移除本项目的副本与登记文件，并清理指向它的关系和正文链接，保留原有文字。引用其他目录的文件或网页时，原件保留。删除公司日常模型后，已保存的历史模型版本仍可打开。
8. 点击本地 Markdown 的文件名或正文中的 Markdown 链接，可在工作台阅读排版后的正文。在项目笔记中，单击哪一段，哪一段就显示 Markdown 源码，周围段落继续排版。点击另一段、移出焦点或按 Esc，当前段落自动恢复排版。↑、↓ 顺着屏幕上的行移动，到段落边界时自动切段并尽量保持光标的横向位置。在段首按退格，或在上一段末尾按向前删除，可合并两段。Tab 和 Shift-Tab 可直接切段。Markdown 表格默认使用 12 像素字号，点格编辑，Tab 切换单元格，↑、↓ 跨行。鼠标移到表格下方会出现正文输入行，点击即可继续写；表格在文末时，也可以从最后一行按 ↓ 进入正文。可直接粘贴电子表格中的多行多列，或通过表格工具增删行列和设置对齐。右键表格可复制、剪切或删除整表。在表内按 ⌘A 选中整表，⌘X 剪切。拖选或按住 Shift 点击可剪切多格；删除最后一行或一列会移除整表，⌘Z 可撤销。实体、概念、事件、问题、报告和 Memo 都支持这种方式。停顿后自动保存，⌘S 可随时结束编辑。拖选报告文字仍可建立引文。从 ChatGPT 或网页复制表格，直接粘贴到正文会生成可编辑的 Markdown 表格；粘贴到已有表格时会从当前单元格填入。粘贴网页摘录会保留链接文字和地址；选中文字后粘贴网址可为其加上链接。截图和图片用 ⌘V 粘贴，图片保存在笔记旁的 assets 目录，正文使用相对路径。文件条目内可点击「保存到知识库 Library」，Codex 会按本机 LakeHouse 的 AGENTS.md 与归档规则保存原件；有多个来源时先选其中一份。工作台核验返回路径，本地文件还会比较原件内容，然后将项目附件引用更新为库内相对路径。原网址和旧项目路径仍可定位同一条资料。

列表内按回车可拆分当前项或续写同级，Shift+回车在同一项内换行。Tab 把当前项及其子项移到上一个同级项下面，Shift+Tab 上移一级，顶层再退一级即转为正文。拖选多个同级项可一起调整。新建的空项已有编号，直接输入正文即可，也可以输入 `- ` 切换为圆点。数字与圆点可以交替嵌套，⌘Z 可撤销结构调整。

## 自定义预研 skill 的文件约定

Codex 启动后可以从当前目录的 `project.json` 读取专题名称与研究意图。写入 UTF-8 Markdown，每个对象一个文件。目录决定条目类型。

| 位置 | 用途 |
| --- | --- |
| `reports/base-v1.md` | 基础报告。修订写入 base-v2.md 等新版本，以保留条目的原文位置 |
| `questions/`、`concepts/`、`entities/`、`events/` | 关键问题、概念、实体、事件 |
| `references/` | 参考资料条目，项目附件放入 references/files/ |
| `memo.md`、`log.md` | 个人结论与过程简记 |
| `preflight.done` | 本轮预研核对完毕后最后写入的完成标记 |

例如，`concepts/concept-renewal.md` 的内容如下。数组在 frontmatter 中写成单行 JSON。正文自由使用 Markdown。

```markdown
---
id: "concept-renewal"
title: "续约率"
origin: "预研提取"
links: ["question-renewal"]
anchors: [{"report":"reports/base-v1.md","section":"商业化","quote":"续约率","prefix":"观察","suffix":"的变化"}]
assets: ["library:Library/行业访谈.pdf"]
---
说明分母、观察期间，以及是否包含试点客户。
```

- ID 在项目内跨类型唯一，重命名标题时保留 ID。省略标题时读取第一个一级标题，再回退到文件名；省略来源时，预研目录内的条目默认显示「预研提取」。
- `anchors` 保存可见原文、章节与前后文。没有原文出处时可省略。报告内容使用相对路径，库内文件使用 `library:`，项目附件使用 `project:`。Markdown 正文中的 `[标题](feynman:条目ID)` 可以跳转到对象。
- 问题可用 `answered: true` 表示已回答。合并时，目标文件保存合并内容及 `aliases`，原文件保留，显示端通过别名解析旧引用。普通研究条目删除时会写入 `deleted: true`，并清除项目条目内引用该编号及其旧编号的关联。删除记录可在同步或中断后继续清理。报告和 Memo 内引用该条目的文字仍可阅读，阅读器移除链接。再次预研须尊重合并与删除记录。
- 常规预研和追问将项目目录作为工作目录。选择回写时，工作台额外向 Codex 提供用户配置的知识库目录。研究质量与外部数据源取决于本机配置的 skill。

### 个股项目

个股项目只保存问题、事件和参考资料，概念与实体记在关联专题中。字段的完整说明见 `sling-company-study` 第 3 节。

| 位置 | 用途 | 撰写者 |
| --- | --- | --- |
| `project.json` | 名称、研究缘起（`intent`）、代码、关联的专题实体 | 工作台 |
| `snapshot.json` | 分部、季度序列、估值、反推的隐含预期、一致预期、市场主流说法 | AI |
| `reports/base-v1.md` | 开题研究底稿，可划选建立问题或事件 | AI |
| `questions/` | `role` 为 `crux`（关键问题）、`sub`（子问题，`parent` 指向关键问题）、`flag`（排雷异常，`check` 指向清单项）。AI 起草时写 `candidate: true`、`market_view`、`impact`、`evidence`、`tracking`；`my_view`、`kill` 由用户填写；`depends` 记录引用的专题条目及其指纹 | AI 与用户 |
| `checklist.json` | 排雷清单，状态为 `ok`、`flag`、`na`、`unchecked` | AI |
| `events/` | `date`、`source`，以及 `impacts`：`[{"question":"…","direction":"support|weaken|neutral","note":"…"}]` | AI 与用户 |
| `scenarios.json` | 情景估值 | 工作台 |
| `research.json` | 已发布判断、历史、预测摘要、主模型 | 工作台 |
| `lakehouse.json` | 同步到 Theses 的目标路径和日期 | AI |
| `log.md`、`preflight.done` | 过程日志；开题完成标记 | AI |

## 本地构建与验证

使用 Apple 的 Swift 命令行工具，运行 `./build.sh`。阅读器、xterm.js 5.5.0 终端和本机终端组件随 App 打包，构建和阅读都无需下载依赖。Markdown 解析器的许可证在 Resources/marked-LICENSE.md，xterm.js 的许可证在 Resources/xterm-LICENSE.txt。

`Tests/StorageTests.swift` 检查项目读写、合并、冲突和旧版导入。`Tests/MacSmoke.swift` 使用真实 WebKit 验证渲染与划选，传入 `--terminal` 还会在临时项目中用模拟 CLI 验证内嵌终端、提示词预填、手动发送和完整回答自动保存。MacSmoke 的第一个参数是 Resources 目录，终端测试需要将编译好的 FeynmanTTY 放在测试程序旁。Tests/InlineNoteTests.swift 在临时项目中检查原位编辑、剪贴板与附件预览。界面测试编译时包含应用源文件，使用测试主入口，并将 Resources 打包进测试程序。
